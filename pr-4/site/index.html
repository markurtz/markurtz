    markurtz.com: site documentation¶

    This folder is the complete written record of Mark Kurtz's personal site as decided up to 23 November 2026: what it is for, every page, the data behind it, how it is built and secured, and how it looks and moves. It is written so an engineer, a designer or an AI coding agent can build the production site from these documents and the mock alone, without the conversations that produced them.

    [!IMPORTANT] These documents describe the target site. The implementation in PR #3 was built before most of these decisions were made and differs in routes, access model and schema. The gap and the migration path are listed in engineering/24-build-test-deploy.md.

    How to read this set¶

    Records

    Sources of truth, in order¶

    When two sources disagree, the higher one wins.

    1. Mark's latest message on the point (recorded in the decision log).
    2. These documents.
    3. The static mock, v51 or later (sources). The mock is the visual and behavioural reference: its markup, CSS and scripts are the closest thing to production code.
    4. The "Mark Kurtz Site Structure" spec (Claude Doc). Its client-area section predates the 23 November switch to link-only access and is superseded there by 04-clients-sharing-embeds.md.
    5. The page-content finals (page-review/<page>/final.md), for exact copy.
    6. The implementation plan in docs/plans/website-implementation-plan.md, for stack choices not revisited since.

    Status labels used throughout¶

    Label Meaning
    Locked Mark approved it. Change only with his say-so.
    Default An engineering choice made on his behalf. Safe to change if a better option appears; note it in the decision log.
    Open Waits on Mark. Listed in 06-open-decisions.md.
    Held Content that is in the mock as a stand-in and must not go live until Mark supplies the real fact.

    Requirement IDs¶

    Requirements carry stable IDs so tests, issues and pull requests can cite them: PRD-* product, IA-* structure, PG-* page, CL-* clients, DATA-* content and schema, SEC-* security, FE-* front end, NFR-* quality, DS-* design, ART-* art and motion.

    Keeping this set current¶

    • A pull request that changes behaviour updates the document that describes it, in the same PR.
    • A new decision from Mark goes into the decision log first, then into the document it touches.
    • Never invent biography, employers, dates or publications. Unknown facts are Held and use the placeholder convention in 05-voice-copy-placeholders.md.
