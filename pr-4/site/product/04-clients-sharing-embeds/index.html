    04 · Clients, sharing and embeds¶

    Status: Locked 2026-11-23 (link-only access, mock v48; share buttons and embeds, mock v51; buttons in the photo viewer requested the same day). This document supersedes the access-code and sign-in wording in the structure spec and in the Studio page final.

    1. What the client area is for¶

    A general area for hosted work: photography first, films beside the photos, files later. Mark delivers a shoot; the client sees every photo in the order it happened, downloads them if allowed, and shares some of them with family and friends without Mark's help. Nothing in it is public, except what a client deliberately shares.

    2. The model: the link is the key¶

    There are no accounts, passwords, access codes or sign-in pages for clients.

    • CL-1 Every client address is opened by a link. A link is an address plus a signed token (a JWT) after #: https://<domain>/clients/#<token> for links Mark makes, and https://<domain>/s/<id>/#<token> for shares made from them.
    • CL-2 The part after # never reaches the server on page load, server logs, Referer headers or link-preview bots. The page script reads it.
    • CL-3 The browser keeps the token in a cookie so the client does not need the link again; the script sends it to the API in an Authorization: Bearer header. "Forget this browser" deletes it. Forgetting does not turn the link off.
    • CL-4 The token in the link and the server's record must both agree: a valid signature alone never grants access; the link must exist and be active in the database on every request, so turning a link off takes effect on the next request (21).
    • CL-5 There is no difference between "a link" and "a code": the token is the only secret. Pasting the whole link, or just the part after #, into "Paste your link" works the same.

    3. What a link allows¶

    Every link states three permissions. Each is off unless granted (Locked 2026-11-23):

    Permission Lets the holder Shown as
    Download Save full-size originals, one by one or all as a zip "Download · Save the full-size photos"
    Share single photos Copy a link to any one photo or film "Share single photos · Copy a link to any one photo or film"
    Make new shares Select photos and make a new link from them "Make new shares · Pick photos and make a new link from them"

    Viewing is always allowed. Rules:

    • CL-10 A link never allows more than the link it was made from. The share sheet disables a permission the holder does not have.
    • CL-11 A link covers either a collection (everything in it, including later deliveries), a selection (a fixed list of items), a filter of a collection that "keeps updated", or a single item.
    • CL-12 Turning a link off ends it everywhere it was opened, and every link made from it, however deep. Turned-off links open /link-expired/.
    • CL-13 Links last until turned off. There is no expiry by default (Locked P5.7). Mark can set an expiry in /admin (Default).
    • CL-14 A link made by a client belongs to the link it was made from. The holder of a link sees and can turn off every link made from it ("Links you've made"); Mark sees all of them.

    4. Link previews for shares¶

    Preview bots (Slack, iMessage, X, WhatsApp) never see the # part, so a share address carries a random path id: /s/<id>/#<token> (Locked 2026-11-23).

    • CL-20 With the path id alone, the server renders only og: tags: title "", description "N photos by Mark Kurtz, shared with you.", and a 1200 × 630 preview crop of the first photo. Nothing else: no list of items, no full-size media.
    • CL-21 Each share has a "Show a preview when the link is pasted" option, on by default, noting "a small copy of the first photo, visible to whoever has the link". Off: the preview shows the generic Clients banner.
    • CL-22 The full page (all items, full sizes, downloads) needs the token.
    • CL-23 /s/ is allowed in robots.txt so bots can fetch the preview; every share page sends noindex and stays out of the sitemap. /clients/ stays disallowed.
    • CL-24 /clients/#<token> links from Mark use the generic Clients banner as their preview.

    5. Pages¶

    5.1 /clients/: Open your photos / Your photos¶

    • With no stored token: the "Open your photos" card (03). Opening a link stores the token and removes the #… from the address bar (history.replaceState).
    • With a stored token: "Your photos": what this link allows (three checks), From Mark (collections the link covers, each with "N new · More on the way" and "N photos so far"), and Links you've made.
    • Links you've made lists, per link: name, photo stack and count, the source collection, date, the three permissions, "Show a preview" state, Active or Turned off, Copy and Turn off. Turn off asks for confirmation inline ("Turn off? Everyone with this link, and any links made from it, loses access." · Turn off · Keep) before it acts.
    • A summary line counts links and how many are active.

    5.2 /clients/g/<id>/: one collection¶

    • CL-30 Order. Every photo in capture order on the timeline rail, scaled to the range of the photos: clock times for a single day, days for a trip, months for anything longer, with a range bar on top. Moments group photos (for a wedding: Getting ready, Ceremony, Portraits, Reception).
    • CL-31 Filters. Mark tags photos ahead of time in five facets: Part of the day, Where, Who, Kind, Delivery (New). The toolbar shows an All/New switch and dropdown checkbox menus for the other four. Picks within a facet combine with OR, across facets with AND. Filters live in ?f=. The count line reads "N photos, in the order taken"; "Clear filters" resets.
    • CL-32 Select. A check circle on each photo (no hearts or favourites). "Select all N" selects only what is showing. A sticky bar shows "N selected · Clear · Make a link". Selection controls appear only when the link allows Make new shares.
    • CL-33 Make a link (share sheet): thumbnails of the selection; Name (prefilled from the filter, e.g. "Family"); "What the link lets them do" with the three permissions (Share single photos on by default, others off, unavailable ones disabled) and the note "Anyone with the link can view. A link never allows more than yours does."; Keep it updated (only when made from a filter: "add new photos that match as Mark delivers them"); Show a preview (on); buttons Make link and Cancel. The new link is copied and appears under "Links you've made".
    • CL-34 Deliveries. Mark delivers in batches. New photos carry a New badge until the holder has seen them; the meta line notes the next delivery ("Next delivery ").
    • CL-35 Download all (when allowed) requests a short-lived link to a zip.
    • CL-36 Films sit in the same timeline and viewer as photos, with a play mark.

    5.3 /s/<id>/: a share¶

    Shows exactly what the share covers, view only plus what it allows. One item shows large; several show as justified rows. "See more of my work" links to /studio/. No path back to the source collection.

    5.4 /link-expired/¶

    For any turned-off or unknown token. Same answer for "turned off", "never existed" and "malformed", so nothing can be guessed.

    6. The three buttons on every photo and film¶

    Every photo and film, in Studio and in Clients, carries the same three round buttons in its top right, on cards, on its own page and in the full-screen photo viewer (Mark, 2026-11-23: the viewer currently shows only Copy link and Close and must show all three).

    Studio photos and films¶

    Button Action

    Embed Copies an iframe snippet for /embed/studio/<work>/<n>/, with width, height and title. A popover shows the snippet with Copy.
