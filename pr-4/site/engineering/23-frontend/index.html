    23 · Front-end implementation¶

    Status: behaviour Locked (mock v51 is the reference); component boundaries Default.

    The mock is real HTML, CSS and JavaScript generated by a dependency-free Node script (site-mock/). Production ports it to React server components with small client islands. Port markup and CSS faithfully; the look was approved on the mock, not on a description of it.

    1. Rules¶

    • FE-1 Server components by default. "use client" only for the islands in § 3.
    • FE-2 HTML first. Every list renders every item in HTML; scripts only hide and show. Links, filters (as links with query strings), the contact form and downloads work without JavaScript.
    • FE-3 Port the CSS, don't restyle. tokens.css is generated from tokens.json (W3C DTCG) and never hand-edited. site.css is split into one file per component; selectors and values stay the same. Cascade layers: reset, tokens, base, components, utilities. (The mock keeps its CSS unlayered only because the artifact host injects its own body font; production does not need that.)
    • FE-4 One icon helper. icon(name, label, size) from icons.mjs becomes <Icon name label size>; inline SVG, currentColor, aria-hidden unless labelled (32).
    • FE-5 Reserve space. Every image and video has width/height or aspect-ratio.
    • FE-6 Motion respects the user. prefers-reduced-motion sets every duration to 0 and art to stills.
    • FE-7 One strings file. Interface copy lives in src/lib/strings.ts, not inline.

    3. Islands and their behaviour¶

    List filters and search (<ListControls>)¶

    • Reads q, year and the page's filter keys from the URL on load; applies them by toggling hidden on items and year groups; updates counts, the count line and the jump bar.
    • Writes the URL with history.replaceState (no history entry per keystroke).
    • Search: MiniSearch over the page's index JSON (titles, summaries, labels), prefix and fuzzy 0.2. The index loads on first focus of the search box.
    • Blog: section filter reveals its sub-label options.
    • Without JavaScript: filter options are links to ?key=value; the server-rendered page is the full list, so the link still lands on the right page (filtering itself needs JS; acceptable).

    Contact dialog¶

    <dialog> with focus trap, Escape closes, focus returns to the opener. Turnstile loads when the dialog first opens. Errors in words under each field; submit disabled while sending; success message replaces the form.

    Theme¶

    Three states (System, Light, Dark) on one icon button whose label says which. Stored in localStorage (mk-theme), applied as data-theme on <html> by an inline script before paint.

    4. Item actions: Copy link · Embed · More¶

    One component for every photo and film on cards, item pages, the viewer and client galleries (04 § 6).

    • Three 36 px round buttons, top right, on a translucent dark chip; visible on hover and focus on pointer devices, always visible on touch.
    • Copy uses navigator.clipboard.writeText; a toast (role="status") confirms. Client copies first POST /api/links, then copy; the toast offers "Change".
    • Embed opens a small popover with the snippet in a read-only field and Copy; client embeds add the warning line.
    • More is a menu button (aria-haspopup="menu"), arrow keys move, Escape closes. Share… uses navigator.share and is hidden where unsupported.
    • The component takes { kind: "studio" | "client", href, embedSrc, title, credit, can } and renders only what can allows.

    5. Viewer¶

    • <dialog> that is always dark, photo first, filling the viewport.
    • Round 44 px previous and next buttons at the sides; Copy link, Embed, More and Close top right (Mark, 2026-11-23).
    • Bottom gradient with caption, mono "4 / 6" count and a thumbnail filmstrip; current thumbnail outlined in teal; the strip hides under 600 px.
    • Arrow keys and swipe move; Escape closes; focus returns to the opening thumbnail.
    • Films sit in the same set with a play mark; they play in place with controls clear of the strip and pause when the viewer moves on.
    • The URL updates to the item page (/studio/<work>/<n>/) with replaceState while open, so a copied address bar matches the photo; closing restores the work page URL.
    • Client viewer: previews are the signed 2560 px images; next items preload one ahead.

    6. Client app (<ClientApp>)¶

    A single island mounted on /clients/, /clients/g/[id]/, /s/[id]/ and /s/[id]/embed/.

    1. On load: read and strip location.hash; merge into __Host-mk_links; pick the token for this page (the share's own id on /s/, else the most recent root link that covers the collection).
    2. Fetch /api/links/current and, on a gallery, /api/collections/:id. On 404, go to /link-expired/.
    3. Render with the same components as Studio (<PhotoTimeline>, <JustifiedRows>, <Viewer>, <ItemActions kind="client">).
    4. Facet filters: OR within a facet, AND across; ?f=stage:Ceremony,people:Family; "Select all N" selects what is shown; the selection bar is sticky at the bottom.
    5. Share sheet: <dialog> form (Name, three permissions limited by the current link, Keep it updated when made from a filter, Show a preview), POST /api/links, copy the result.
    6. "Links you've made": list with Copy, Turn off (inline confirm), DELETE /api/links/:id.
    7. "Forget this browser" deletes this link's cookie entry and returns to "Open your photos".

    7. Page transitions, print and machines¶

    • Cross-document view transitions (@view-transition { navigation: auto; }) with a short fade; page art and the header keep stable view-transition-names.
    • Speculation rules prefetch same-origin links on hover (eagerness: moderate) for public pages only; never for /clients/, /s/, /api/.
    • Print CSS: /professional/ prints as a résumé ("Download résumé" calls window.print()).
    • Structured data (JSON-LD): Person on home and About; ScholarlyArticle per paper; CreativeWork / Photograph / VideoObject on Studio items; BlogPosting on hosted posts; BreadcrumbList from the path title.

    8. Porting checklist per page¶

    1. Copy markup from the mock's dist/<route>/index.html and the builder in site-mock/scripts/build.mjs.
    2. Replace content literals with the typed content queries.
    3. Move the page's CSS from site.css into its components.
    4. Wire islands.
    5. Visual diff against the mock at 390, 768, 1280 and 1920 px, light and dark (Playwright screenshots; tolerance 0.5%).
    6. axe: no violations. Keyboard pass: every control reachable and visible on focus.
